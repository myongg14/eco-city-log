# 에코시티 기록장

고2 「실제 기능을 갖춘 친환경 도시 모형」 프로젝트의 활동 기록 사이트입니다.
GitHub Pages(화면)와 Supabase(데이터베이스·로그인)로 돌아가며, 모두 무료 요금제로 씁니다.
카톡방에 사이트 주소를 올리면 각자 아이디와 비밀번호만으로 들어올 수 있어요.

## 처음 한 번만 하는 설정 (관리자)

### 1. 데이터베이스 만들기
1. Supabase 대시보드 → 왼쪽 메뉴 **SQL Editor** → **New query**
2. `supabase/01_foundation.sql` 파일 내용을 전부 복사해 붙여 넣고 **Run**
3. 맨 아래 결과에 `33`이 나오면 성공이에요. (학생 21 + 예비 10 + admin + teacher)

여러 번 실행해도 계정이 중복으로 생기지 않아요.

그다음 같은 방법으로 아래 파일을 차례대로 실행해요.
- `supabase/02_records.sql`: 계획서·이론 조사·활동 일지. 결과에 표 이름 4개가 나오면 성공이에요.
- `supabase/03_team_supplies.sql`: 공지·할 일·물품 신청·예산·일지 사진 기록. 결과에 표 이름 5개가 나오면 성공이에요.
- `supabase/04_photos_storage.sql`: 사진 파일 저장소(비공개 버킷 `photos`). 결과에 `photos`가 나오면 성공이에요. 사진은 로그인한 사람만 볼 수 있고, 학생은 자기 폴더에만 올리고 지울 수 있어요.
- `supabase/05_reflection_feedback.sql`: 성찰·선생님 피드백 댓글·교과 연계 태그. 결과에 표 이름 3개(comment_seen, comments, reflections)가 나오면 성공이에요.
- `supabase/06_schedule_roles.sql`: 통합 일정·통합 테스트 체크리스트·역할 분담과 변경 이력·알림 확인 시각. 결과에 표 이름 5개가 나오면 성공이에요.
- `supabase/07_progress_feedback.sql`: 기능 구현 현황·실험·측정 기록장·친구 칭찬·조언·팀 간 요청과 답변. 결과에 표 이름 5개가 나오면 성공이에요.
- `supabase/08_links_showcase.sql`: 팀 간 연결 지도, 외부 공개 페이지(처음엔 꺼짐, 관리자·선생님이 켬). 로그인하지 않은 사람은 `public_showcase()` 함수로 학생 이름을 뺀 요약만 받고, 고른 사진만 볼 수 있어요. 결과에 표 이름 2개(showcase_items, team_links)가 나오면 성공이에요.
SQL 파일은 **번호 순서대로** 실행해요. 01을 다시 실행했다면 그 뒤 파일들도 다시 실행해 주세요(함수 실행 권한이 초기화돼요).

### 2. 아무나 가입하지 못하게 막기
**Authentication → Sign In / Providers**(또는 Settings)에서 **Allow new users to sign up** 을 끕니다.
계정은 위 SQL과 관리 화면에서만 만들어요.

### 3. 사이트 공개하기
GitHub 저장소 → **Settings → Pages** → Source를 **Deploy from a branch**, Branch를 **main / (root)** 로 두고 Save.
1~2분 뒤 `https://myongg14.github.io/eco-city-log/` 에서 열립니다. 이 주소를 카톡방에 올리면 돼요.

## 보안 약속
- Supabase의 **service_role 키, Secret 키(sb_secret_…), Database 비밀번호**는 이 저장소, 코드, 채팅 어디에도 넣지 않아요.
- 코드에 들어간 `sb_publishable_…` 키는 공개돼도 괜찮은 키예요. 실제 보호는 데이터베이스의 RLS 규칙과 함수 권한이 맡아요.

## 문제가 생기면
- **아이디·비밀번호가 맞는데 로그인이 안 돼요**: Supabase가 `@ecocity.invalid` 형식의 가짜 이메일을 거부할 수 있어요.
  `js/config.js`의 `LOGIN_EMAIL_DOMAIN`과 SQL의 `private.login_email` 함수에서 도메인을 같은 값(예: `ecocity.example.com`)으로 바꾼 뒤,
  SQL Editor에서 아래를 실행하세요.
  ```sql
  update auth.users set email = replace(email, '@ecocity.invalid', '@새도메인');
  update auth.identities set identity_data = jsonb_set(identity_data, '{email}',
    to_jsonb(replace(identity_data->>'email', '@ecocity.invalid', '@새도메인')));
  ```
- **사이트가 갑자기 안 열려요**: Supabase 무료 프로젝트는 1주일 넘게 아무도 안 쓰면 일시 정지돼요. 대시보드에서 **Restore project** 를 누르면 돼요.
- **화면이 예전 그대로예요**: 새로고침(모바일은 앱을 닫았다 열기)을 해 보세요.

## 데이터 모델에서 바꾼 점
- 모든 쓰기는 데이터베이스 함수(`save_plan`, `save_research`, `save_log` 등)로만 해요. 표에는 읽기 권한만 열어 두고, 함수 안에서 "쓴 사람만 고치기·지우기", 필수 항목, 링크 형식(http/https만)을 검사해요.
- 기록은 학생 계정만 쓸 수 있어요. 관리자·선생님은 모든 기록을 읽어요.
- 꺼진 예비 팀 학생의 기록은 관리자·선생님만 볼 수 있어요.
- 활동 시간은 일지마다 적지만 자동으로 합치지는 않아요(사용자 요청).
- 보유 물품은 따로 표를 두지 않고, 물품 신청 중 '수령' 상태인 것을 보유 물품으로 보여 줘요.
- 예산에서 '쓴 금액'은 선생님이 승인한 뒤(승인·구매 완료·수령)의 합계예요. 신청 상태는 '승인 대기'로 따로 보여요.
- 할 일 보드의 할 일은 관리자·선생님이 만들고, 맡은 학생은 상태(예정·진행·완료)만 바꿔요. 팀 진행률은 그 팀 할 일 중 완료 비율이에요.
- 사진은 올리기 전에 긴 변 1600px JPEG로 줄여서 무료 저장 공간(1GB)을 아껴요. 일지 하나에 6장까지예요.
- 성찰은 쓴 학생과 관리자·선생님만 읽어요(친구 기록은 서로 보지만 성찰은 개인적인 글이라서). 주간 성찰은 한 주에 하나, 최종 성찰은 한 사람에 하나예요.
- 피드백 댓글은 `comments` 표 하나에 일지·조사·성찰 댓글을 모두 담아요. 기록을 쓴 학생, 댓글 쓴 사람, 관리자·선생님만 읽어요. 관리자·선생님이 남기고, 기록을 쓴 학생은 답글을 달 수 있어요. 기록을 지우면 댓글도 지워져요.
- 알림은 따로 표를 두지 않고, `comment_seen`(마지막으로 내 기록을 확인한 시각)보다 늦게 달린 댓글을 새 피드백으로 보여 줘요.
- 교과 연계는 일지·조사의 `subjects` 칸에 담고, `set_record_subjects` 함수로 따로 저장해요(기존 저장 함수를 바꾸지 않으려고).
- 생기부 정리는 AI를 쓰지 않고 화면에서 규칙과 틀로 만들어요. 본인이 쓰거나 참여자로 표시된 기록만 들어가요.
- 전체 백업은 로그인한 관리자·선생님 화면에서 읽을 수 있는 표를 모아 JSON 한 파일로 받아요. 비밀번호는 들어가지 않고, 사진 파일은 경로만 들어가요.
- 통합 일정 달력에는 `schedule_events`와 할 일 보드의 마감일을 함께 보여 줘요. 일정은 관리자·선생님이 만들어요.
- 통합 테스트 항목은 관리자·선생님이 만들고, 결과(대기·통과·실패)는 맡은 팀 학생이 기록해요. 팀을 비워 둔 항목은 모든 학생이 기록할 수 있어요. 실패는 메모가 꼭 있어야 해요.
- 역할 분담은 `role_assignments`, 바뀐 날짜와 이유는 `role_history`에 자동으로 남아요. 담당자·분야·세부 업무를 바꾸면 이유를 꼭 적어야 해요.
- 알림은 따로 표에 쌓지 않고 할 일, 물품, 댓글, 일정, 통합 테스트에서 그때그때 모아 보여 줘요. `notification_seen`보다 늦게 생긴 것만 '새로'로 세요.
